# Service acceptance gate

All boxes are initially pending. Record evidence, tester, date and approver in the private project copy; never interpret this template as a certification.

- [ ] Requirements, scope, exclusions and service objectives approved.
- [ ] Product version/edition, license, cost and residency reviewed.
- [ ] Architecture, ADRs, owner/deputy and release manifest current.
- [ ] HTTPS, authentication, mail, editing, collaboration, search and attachments tested.
- [ ] Negative access tests pass for pages, files, search, exports and shared links.
- [ ] Monitoring sends a test alert to the actual support owner.
- [ ] Backup copied independently; clean isolated restore completed within agreed objectives.
- [ ] Migration counts reconcile; all critical content accepted; exceptions owned.
- [ ] Update/rollback and disaster-recovery procedures understood and exercised as required.
- [ ] A second administrator performs a representative operational task unaided.
- [ ] Users complete onboarding tasks and know where to request help/access.
- [ ] Source retirement, retention, review cadence and support transition approved.

Decision: accepted / conditionally accepted / rejected. Critical security, recovery or content-integrity failures prohibit acceptance. Conditional acceptance requires a noncritical exception, accountable approver, mitigation and deadline. Record signature/date in the customer's system of record.
