# Authoring templates

Copy a template into the selected platform or private content repository and replace bracketed fields. Keep stable IDs and ownership metadata. Do not publish a template with placeholders as if it were accepted documentation.

| Template | Use |
| --- | --- |
| [System / Dienst](system-documentation.md) | Core template: canonical infrastructure/service description |
| [Application documentation](application-documentation.md) | Runtime, integrations and application operations |
| [Workflow / Runbook](runbook.md) | Core template: repeatable task, expected outcome and recovery |
| [Troubleshooting](troubleshooting.md) | Evidence-led symptom diagnosis |
| [Project handover](project-handover.md) | Scope, delivery, risks and acceptance |
| [Knowledge transfer](knowledge-transfer.md) | Capture and verify tacit operational knowledge |

## Docmost baseline

Under `00 Documentation → 90 - Vorlagen`, maintain the two core templates as `System / Dienst` and `Workflow / Runbook`. Application documentation and troubleshooting are optional specialist extensions; handover and knowledge-transfer templates remain available for their own tasks. Do not create competing system and application pages for the same facts.

The [system overview](system-overview.md) is a separate normal table page under `20 Systeme & Dienste`, not a third core authoring template or a paid Base. Follow the [space structure](../governance/docmost-structure.md) and [change boundary](../governance/change-boundary.md).
