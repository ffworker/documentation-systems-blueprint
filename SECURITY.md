# Security reporting

Do not post secrets or sensitive deployment details in a public issue. For a vulnerability in this blueprint, use GitHub private vulnerability reporting if enabled. If unavailable, ask the maintainer for a private reporting channel without publishing exploit details. Upstream application vulnerabilities should go through the relevant vendor's security process.

This repository contains examples, not a managed production service. Deployers own patching, infrastructure controls and acceptance. Current limitations are documented in the validation record and operational runbooks.
